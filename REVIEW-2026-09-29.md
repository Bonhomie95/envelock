# Local product and security review — 29 September 2026

The product is an AI-assisted email threat detector covering payment fraud, phishing, impersonation, and integration-dependent identity/mailbox threats. It is not a general detector of AI-generated content. The landing page now explains that scope, the role of contextual AI review, and the limits of each connection. No changes were pushed or deployed.

## Delivered

- Rebuilt the landing page around an interactive, explicitly illustrative detection preview, readable evidence, clear next actions, real domain scanning, and plan-specific pricing.
- Refreshed the shared client/admin design system, dashboard hierarchy, detection lab, and authentication layout. Removed the requested onboarding and free-Guard sidebars from both authentication modes.
- Unified the font family across the public website, signed-in client, admin interface, and shared sensor UI. Removed the external Google Fonts request; updated the favicon.
- Added staged hero entrances, one-time scroll reveals, preview/result transitions, button/card hover feedback, and menu/dialog/toast motion. Motion respects reduced-motion preferences; no autoplaying carousel or continuous marketing animation was introduced.
- Improved dialog/drawer keyboard focus, dashboard tab navigation, analysis-result focus, and loading/error messaging.
- Corrected stale analysis results, editable-sample context leakage, and critical-alert prioritization in the dashboard summary.

## Security corrections

| Finding | Correction and verification |
| --- | --- |
| Provider network/JSON/envelope errors could escape the intended AI failure path or carry sensitive provider text into diagnostics | Normalize failures into sanitized errors; rule processing continues. Added malformed response, HTTP/network error, and log-redaction tests. |
| Non-finite AI confidence and malformed usage values | Require finite confidence; safely parse usage counters. Regression coverage includes NaN/infinity. |
| Untrusted attachment filenames were included in the trusted-facts portion of the AI prompt | Include attachment count only in that trusted context; regression test checks filename exclusion. |
| A small compressed DOCX could expand excessively before parsing | Check ZIP central-directory expansion budget (30 MiB) and entry count (1,000) before parsing; test verifies rejection before the XML parser. Added a 10-second OCR timeout. This is not a full parser sandbox. |
| Known dependency advisories | Updated client development dependencies and required PyJWT >=2.14.0; installed local PyJWT 2.15.1. Audits reported no known vulnerabilities for the installed Python environment and client/admin npm dependency sets. |

A targeted scan of 425 tracked text files found no matches for the tested high-confidence credential patterns (AWS access IDs, live Stripe keys, OpenAI project keys, GitHub classic tokens, private-key PEM headers). This was not an exhaustive secret/entropy scan or a Git-history scan. The existing server environment file is ignored and was not printed or used by the isolated preview.

## What remains unverified

This was a code/documentation review, local test pass, dependency audit, and browser smoke test, not an independent penetration test or proof that the entire codebase is vulnerability-free. Architecture and launch documentation, application flows, detection/AI boundaries, authentication and tenant isolation paths, parsers, and test coverage informed the changes; this report does not claim a line-by-line manual audit of every file.

Real Microsoft/Google consent and mail delivery, provider permissions, live IMAP/SMTP, external reputation APIs, paid AI-provider behavior, real Stripe checkout/webhooks, SMS, and deployed DNS/reverse-proxy/security settings require their own end-to-end acceptance checks. The existing launch guide describes several of those prerequisites. No production mailbox, customer data, billing transaction, external notification, or deployment was exercised here. Attachment processing is still in-process and merits resource-isolated execution for hostile production workloads. The existing type-error baseline and deprecation warnings remain technical debt.
